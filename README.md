# Plan Do See Diary

과제 6용 공개 Plan → Do → See 다이어리입니다. 로그인 없이 누구나 열 수 있으므로 공개 가능한 일정만 저장합니다.

## 저장 구조

- `plans`: 계획 ID, 기간, 우선순위, 성공 기준, 예상 시간, 다음 계획
- `tasks`: 계획에 연결된 할 일, 마감일, 우선순위, 태그, 예상 시간, 상태
- `executions`: 할 일에 연결된 시작·종료 시각, 실제 분, 막힌 이유
- 저장소: Cloudflare D1 (`DB` binding)
- 시간대: `Asia/Seoul`
- 시간 길이 단위: `minutes`
- 계약: `contracts/pds-schema-v2.json`

## 원본 데이터 이관

사용자가 제공한 `9월 주간 계획표`, `10월 주간 계획표` PDF에서 날짜·할 일·체크 상태를 이관했습니다. 원본에 없던 우선순위와 예상 시간은 임시값으로 표시하고 `needs_review=1`로 저장합니다. PDF에 실제 시작·종료 시각이 없으므로 실행 기록은 임의로 만들지 않습니다.

## 주요 기능

- 계획 수정 시 같은 ID 유지
- 할 일 생성·수정·완료·다시 열기·삭제
- 서버 검색·필터·2가지 이상 정렬
- 실제 실행 기록 저장과 동일 할 일 중복 완료 방지
- 회고 숫자에서 해당 기록 목록으로 이동
- 전체 JSON 내보내기·가져오기
- 스크립트 모양 문자열을 React 텍스트로 안전하게 표시

## 로컬 검사

```bash
pnpm db:generate
pnpm lint
pnpm build
```
# 하루별 화면

기본 화면은 Asia/Seoul 기준 오늘의 기록입니다. 월·날짜 선택, 전날/다음 날, 오늘 버튼으로 이동합니다. Plan에서 할 일·우선순위·예상 시간을 정하고 Do에서 실행과 실제 시간을 기록합니다. See에는 완료·미완료·이월 수와 예상/실제 시간이 표시됩니다. `scheduled_date`는 계획일이며 `due_date`(마감일)와 별개입니다.

새 계획은 미완료 시 자동 이월이 기본으로 켜집니다. 한국 날짜가 바뀐 뒤 첫 조회에서 이전 기록은 `carried`로 남고 다음 날짜에 새 기록이 이어집니다. `carried_from_task_id` 유일성으로 여러 번 조회해도 같은 항목이 중복 이월되지 않습니다. 사이트가 닫혀 있었다면 다시 열 때 지난 날짜를 차례대로 처리합니다. 오래 접속하지 않은 경우 최대 31일을 순서대로 처리하고 오늘로 이어갑니다. 과거 Notion PDF의 미완료 항목은 한꺼번에 오늘로 몰리지 않도록 기본 자동 이월 대상에서 제외합니다. 필요하면 해당 항목을 수정해 자동 이월을 켤 수 있습니다.

Plan의 성공 기준과 See의 다음 계획 한 줄은 선택한 날짜의 하루 계획(`PDS-DAY-YYYY-MM-DD`)에 각각 저장합니다. 같은 날짜로 돌아오면 저장한 문구가 다시 나타납니다. See에서 남긴 한 줄은 바로 다음 날짜의 Plan에도 표시됩니다. 전체 JSON 내보내기·가져오기에도 포함되며, 기존 `plans` 열을 사용하므로 DB 구조 변경은 없습니다.
